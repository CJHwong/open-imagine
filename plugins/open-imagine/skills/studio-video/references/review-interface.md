# One shared review interface

Use `assets/review.html` through `scripts/review.py build project.json` for all production reviews. Do not create a new page design for each film, stage or revision. Change the shared template when improving the interface; keep project content in its manifest. Preserve existing pages before replacing them and retain local drafts through the project/revision storage key.

## Stable layout

- Compact project/revision bar and feedback export; no hero, promotional copy or production essay.
- Persistent modes: Storyboard, Shots, Edit, Cast & sound. Show unavailable modes disabled with a reason. Start on the assembled edit when available, otherwise the storyboard.
- Same desktop positions: picture above a horizontal thumbnail filmstrip, version/decision/notes inspector right. Fit both portrait and landscape without cropping faces or changing the page shell. Thumbnail shape follows the project aspect ratio; preserve enough size to judge the composition.
- Use a restrained neutral-gray screening workspace with one quiet selection accent, readable timecode and compact transport controls. The picture and usable thumbnails take priority over decoration. Avoid colored dashboard cards, redundant labels or pretending that extra panel borders make a professional interface. Keep any shot-duration timeline compact and accurate; it must not compete with the filmstrip or become a fake editing feature.
- Left/right keys select the previous/next thumbnail in the same horizontal order shown on screen, including after clicking mode tabs, navigation buttons or native video controls. Scroll the active thumbnail into view. Do not pair left/right navigation with a vertical thumbnail list. Leave up/down for ordinary page/control scrolling. Do not intercept cursor movement in text inputs, selects or editable content. Space plays/pauses available video. Display the shortcuts discreetly; capture navigation before native media/tab key handlers consume it. Mode switches remain available through clicks and Tab/Enter.
- Mobile keeps the same functions: picture, horizontally scrollable items, then inspector. No horizontal page overflow. Keep all viewer controls accessible.
- Overview is an optional contact sheet inside the viewer; selecting a frame returns to focused review. Cast images and playable voice/script samples use the same viewer/inspector.
- Action/sound/continuity, reference/motion plans and technical provenance are expandable. Essential warning states remain visible. No broken player or fictitious generated asset when only plans exist.
- A "How it was made" section under the inspector shows, for the selected version, each `generation` step in order: model, mode, seed and settings, the prompt as sent, numbered reference thumbnails in the order the model received them, and the operation ID. Under it, every dialogue line and sound file of the shot gets a player and its own steps, clone references included. Show only steps read from saved request or metadata files; a step with no record stays absent.

Show every record as rendered text: labels and values, thumbnails and players. Never print raw JSON. Show each fact once: if the title, the summary and a detail field hold the same text, keep the first. Collapse each prompt to a two-line preview that opens on click, so the reference thumbnails stay in view. A click on any thumbnail opens the image in a modal over the page, not the raw file. Esc or a click outside closes it, and while it is open the arrow keys step through the panel's images instead of changing shots. The arrow keys always navigate: shots on the page, images in the modal. Space plays the current shot and stops at its end; it does not advance. A shot clip carries handles and only its model soundtrack, so back-to-back clips misstate the timing. Continuous playback belongs to the Edit tab, which plays the assembled cut.

"Copy prompt" sits beside "Export feedback". One click collects every item the reviewer changed on the page, across all modes, into one Markdown prompt and copies it: a note, a decision or a take that differs from the manifest. The prompt holds the project, revision, mode and storyboard version, then one section per item in shot order, then assets: decision, selected take and its file, the base take if it changed, the generation steps with their settings (not the prompts), the playhead times in the note, the note verbatim and the other takes' decisions. With nothing changed, a toast says so and nothing is copied. When the clipboard refuses, as on file:// or without permission, a dialog shows the prompt with the text selected. The JSON export stays the record that `review.py feedback` imports. `buildPrompt` sits between the `prompt-builder` markers as a pure function, and `scripts/test_review_prompt.py` runs it in node.

Notes and take decisions persist per project/revision and per version. Preserve original selected versions as the feedback base; changing a candidate in the browser is a draft until exported/imported. Export must work without a backend. Per-version Keep decisions are not storyboard approval. Record approval with `review.py approve`.

Use clear time scopes: assembled-edit playhead timestamps vs individual source-clip timestamps. Do not add the shot's timeline start to a raw source time unless an actual source-to-edit mapping supports it. Keep per-take source ranges and available handles in provenance.

## Verify changes once

Check a storyboard-only project, portrait motion edit and landscape motion edit against the same template. Verify media loads, active-item and version changes, local note restoration, feedback export/import roundtrip, empty assets, video seeking and voice playback controls. Exercise the narrow mobile layout and inspect screenshots. Verify no cross-project media or storage mixing. Test schema/helper behaviour separately from artistic quality; interface validation cannot approve film content.

Test arrow navigation with focus on a clicked mode tab, previous/next button, video and notes field. The first three must change the shot; notes must retain ordinary caret behaviour. Verify adjacent thumbnails occupy the same row and advance in the key's screen direction, including after the strip scrolls. Check timeline selection, active-thumbnail scrolling and timecode scope. Inspect the theme with actual footage, not just schematic drawings. Interface polish cannot make schematic storyboard drawings into finished character/scene references; label that readiness honestly.

Backward links should lead to the unified page. Avoid maintaining bespoke alternate pages that will drift. Rebuilding a review is authorized routine work; do not overwrite media, user feedback or the storyboard approval record merely to refresh HTML.
